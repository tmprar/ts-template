# 指摘を検証する段階の手順

`verify` は、`find` の全担当の指摘を確かめ直して確かめられた指摘だけを残し、以前のレビューの未解決のスレッドが直っているかを確かめる。
`find` とは別のジョブで起動した Claude のセッションは、指摘を出したときの推測を引き継がずに根拠を開き直すので、この段階で、推測にもとづく指摘を除ける。

1. `gh pr view --comments` で本文を読んで変更の意図をまとめ、`gh pr diff` で差分を読む
2. `claude-review-findings.json` の指摘ごとに、指摘された行と、根拠に挙げられた規約・要件・ADR を開き直し、「残す指摘」に当てはまらない指摘を出力から除く。`title`・`basis`・`detail`・`suggestion` は、確かめた結果に合わせて直してよい
3. 同じ内容の指摘が複数あるときは 1 件にまとめる。`claude-review-threads.json` の未解決のスレッドと同じ内容の指摘は、出力から除く
4. 「再レビュー」に従って未解決のスレッドを確かめ、直っていると確かめたスレッドを、`id` と返信の本文 `reply` の組で `resolved_threads` に並べる
5. `change_summary` に、差分から読み取った、何をどう変えているかを Markdown の段落か箇条書きで書く。PR の作成者が、自分の意図と比べて、レビューが変更を取り違えていないかを確かめるために使う。要約の「変更の要約」の見出しはスクリプトが付けるので、`change_summary` には見出しを書かない

## 残す指摘

出力に残すのは、指摘された行と根拠を読み、規約の文言や要件の記述に反すること、または誤った結果になる入力を確かめた指摘だけにする。
投稿された指摘は PR の作成者が確かめ直すことになり、誤検知は作成者の手間を増やすので、次の指摘は除く。

- 成り立つ条件の一部(呼び出し元、設定の値など)を確かめていない指摘と、推測による指摘
- 誤った指摘、PR が変更していない行の既存の問題、書き方の好み、CI と lefthook が検査する内容

## 再レビュー

`claude-review-threads.json` には、以前のレビューが付けたスレッドのうち未解決のもの(`id`・`path`・`line`・`isOutdated`・`body`)が入っている。

- スレッドの `path` のファイルを開き、現在のコードで指摘の内容が直っているかを確かめる。
  `isOutdated` が true でも、直っているとは判断しない。`isOutdated` は、指摘した行が変更されたことを表すだけで、変更の内容が指摘に対応しているかは表さない
- 直っていないスレッドと、直っているかを判断できないスレッドは、未解決のままにする
- `reply` には、現在のコードのどのファイルのどこが、指摘の内容をどう満たしているかを書く。ワークフローのスクリプトが、`reply` をスレッドに返信してから解決済みにする。解決済みのスレッドは折りたたまれるので、返信が無いと、指摘を読んだ人はどう直ったと判断されたのかを差分から探すことになる。対象のコミットの SHA はスクリプトが書き足すので、`reply` には書かない
- PR の作成者が対応しないと決めた指摘は、解決済みにする対象にしない。コードが変わっていないので、直ったかどうかでは判断できない。
  対応しないと決めた人が、自分でスレッドを解決済みにする
