# 指摘を出す段階の手順

`find` の各担当は、この手順で PR をレビューし、担当する観点のファイルに書かれた観点だけについて指摘を出す。ほかの観点は別の担当が見るため、指摘しない。

意図を知らずに差分を読むと、規約に合っていても目的を満たしていない変更や、意図の一部が実装されていないことを指摘できないので、PR の本文を先に読んで変更の意図をつかみ、差分が意図に沿っているかを確かめる。

1. `gh pr view --comments` で title・本文・base ブランチ・既存のコメントを読み、この PR が何を目的に何を変えるのかをまとめる。
   要件 ID があれば、`docs/requirements.md` のその要件の記述も読む
2. `gh pr diff` で差分を読む。本文に書かれていない変更を見落とさないように、変更されたファイルをすべて読み、ファイルごとに、1 でまとめた意図のどれに対応するかを確かめる
3. 変更されたファイルから、担当の観点のファイルの節のうち、見出しの括弧に書かれた条件に当てはまるものを選ぶ
4. 差分だけで判断できない観点は、観点に書いてあるファイルを開いて確かめる
5. 「指摘の項目」に従って指摘を出力する。指摘が無ければ空の配列にする
